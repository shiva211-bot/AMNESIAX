# Security policy

AMNESIAX is an early-stage project. Do not assume that it is suitable for protecting high-risk activity or sensitive systems.

## Reporting a vulnerability

Please do not publish exploit details for an unpatched vulnerability in a public issue. Use GitHub's private vulnerability reporting feature for this repository if it is enabled. If private reporting is unavailable, open a minimal public issue asking maintainers for a secure contact method; do not include secrets, personal data, or weaponized exploit instructions.

Include the affected revision, platform and version, prerequisites, impact, and a minimal reproduction. Redact credentials, private keys, personal data, and unrelated logs.

## Response expectations

There is no guaranteed response or remediation SLA while the project is in its initial stage. Reports will be triaged based on reproducibility, impact, and affected scope.

## Scope and safe testing

Test only systems and accounts you own or have explicit permission to assess. Do not access, modify, or exfiltrate other people's data. Avoid destructive testing and denial-of-service activity.

## Security claims

A passing unit test or CI run is not proof of end-to-end security. Claims must specify the tested platform, version, configuration, and limitations.
